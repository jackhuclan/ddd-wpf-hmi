## 1. 应用目标

### 1.1 业务目标

面向工厂产线设备提供一台**单窗口桌面监控上位机**，把设备实时数据、告警、工单、配方四类业务集中在一个界面内完成：

1. 以秒级节拍持续采集设备点位数据，并以实时曲线呈现工艺量（温度、压力等）的变化趋势。
2. 点位越限时自动生成告警，支持确认、自动恢复、清除归档与历史分页查询，形成告警闭环。
3. 通过工单把「设备 + 配方 + 执行动作」串起来：创建、指派设备、绑定配方、开始、完成。
4. 配方由配置驱动，工单开始时自动判定版本并决定是否下发/切换，避免人工比对出错。
5. 断网或中心库不可用时不影响本地采集，恢复后通过 Outbox 补同步。

### 1.2 技术目标

- 用 **DDD 限界上下文**切分业务：设备（Device）、工单（WorkOrder）、配方（Recipe）、告警（Alarm）四上下文各自独立建模，上下文之间不直接引用，只通过领域事件联动。
- **领域事件**与 **UI 事件**分离：跨上下文业务规则走 MediatR；界面刷新走应用内事件聚合器；领域层不反向依赖任何 UI 框架。
- **Prism 式模块化外壳**：单窗口 + 左侧导航 + 内容区，模块按需装配/懒加载。
- **插件式数据源**：新增协议只需新增一个数据源实现并注册，采集宿主与主程序不改。
- **配置热加载**：设备、配方、告警阈值、心跳/同步周期来自 `appsettings.json`，修改后点「刷新」即生效，不重启。
- 架构分层可测试：纯业务规则抽成可单测函数。

### 1.3 非目标（本期明确不做）

- 不实现真实 S7 / Modbus RTU / Modbus TCP 物理设备驱动；以内存模拟源（MemorySim）产生数据，但保留数据源接口与四种协议的配置位，便于后续接入。
- 不提供配置文件中设备/配方/阈值的**页面增删改**入口（文章明确「页面不提供增删配置入口」）。
- 不实现用户账号、权限、多租户、远程部署。

## 4. 交互流程

### 4.1 启动与采集

1. 应用启动 → 默认进入「设备监控」页，采集**默认停止**（文章明确「默认门控是停的」）。
2. 点击 **开始采集** → 启动 `PeriodicTimer` 采集循环；按钮变为 **停止采集**；曲线按节拍推进；连接灯变绿。
3. 采集产生点位数据 → 发 `DeviceDataCollectedEvent`：
   - → 告警判定处理器：越限则发 `AlarmRaisedEvent`，活动告警列表实时出现新行；
   - → 图表处理器：转发 UI 事件，曲线推进；
   - → 设备详情页订阅：更新实时值。
4. 值回落到阈值内 → 告警自动 `Recover()`，从活动列表消失。
5. 点击 **停止采集** → `CancellationToken` 取消循环，退出干净，无残留定时器。

### 4.2 告警处理

1. 在活动告警列表选中一行 → **确认** 可用；点击后 `Acknowledge()`（幂等），状态变「已确认」，可重复点不报错。
2. 只有**已确认**的告警，**清除（归档）** 按钮才由灰变可用；点击 `Clear()` 写入历史库，状态变「已清除」。
3. 未确认直接清除 → 实体抛 `InvalidOperationException`，界面按钮置灰从源头拦截。
4. 历史告警：选级别/状态/起止时间 → **查询** → 表格刷新 → `上一页/下一页` 翻页，显示 `当前页 / 总页数 共 N 条`。

### 4.3 工单执行

1. 输入工单号（留空则自动生成 `WO-yyyyMMddHHmmss`）→ **创建工单** → 表格新增一行，状态 `Created`。
2. 选中工单 → 选设备 → 填配方编号 → **指派设备** → 状态 `Assigned`。
3. 选中已指派工单 → **开始执行** → 发 `WorkOrderStartedEvent`（携带 RecipeCode）：
   - 无配方 → 跳过下发；
   - 有配方 → 取最新版 → 与设备当前版本比对 → 一致跳过、不一致切换下发。
4. 选中运行中工单 → **完成（归档）** → 状态 `Completed`。
5. **刷新** 重新读取工单与设备列表，底部统计同步更新。

### 4.4 配方管理

1. 进入配方页 → 展示 `appsettings.json` 中配置的配方列表。
2. 修改配置文件后点 **刷新（重载配置）** → 列表热更新，不重启应用。
3. 选中配方 → **切换下发（激活）** → 走最新版判定流程，激活后状态变「已启用/已下发」。

### 4.5 导航与状态栏

- 点击左侧导航项 → 切换内容区页面，导航选中态高亮，状态栏「当前页」同步更新。
- 工单、配方页面按需懒加载（首次进入时装配）。
- 状态栏右侧实时时钟每秒刷新；连接灯反映采集模块整体连接状态。

## 6. 关键约束

### 6.1 架构约束

- 四个限界上下文彼此**不直接引用**，联动只走领域事件（MediatR）；UI 刷新走应用内事件聚合器。
- 领域层零外部业务依赖，不引用 WPF / Prism / EF Core。
- 设备聚合遵循 **设备 → 通信模块 → 点位** 三级模型；上层按点位读写，不感知底层协议。
- 数据源以插件方式注册，新增协议不改采集宿主。

### 6.2 业务规则约束

- 告警状态机：`Raise → Acknowledge（幂等） → Recover（值回落，与确认相互独立） → Clear（必须先确认，否则抛 InvalidOperationException）`。
- 告警需按「设备 + 点位 + 级别」去重，未恢复前不重复产生活动告警。
- 配方下发：无配方跳过 → 取最新版 → 比对 → 一致跳过 / 不一致切换。
- 工单状态流转单向：Created → Assigned → Running → Completed，不可逆向。

### 6.3 运行时约束

- 采集使用 `PeriodicTimer` + `CancellationToken`，按绝对时间对齐不漂移；采集耗时超过周期不叠加延迟。
- 模块级连接状态机 + 指数退避重连；个别模块离线不得阻塞其它模块的采集循环。
- 配置热加载用 `IOptionsMonitor` 语义，保存即生效，不重启。
- 离线优先：实时数据先写本地 SQLite（WAL），告警经 Outbox 后台同步中心库；断网不影响采集。

### 6.4 数据约束

- SQLite `busy_timeout` 是连接级 PRAGMA，每条连接都要设置。
- Guid 插值格式必须使用 `:N0` 之外的合法格式（文章中曾因 `:N0` 非法导致「假失败」）。
- UI 计算属性的 `CanExecute` 必须显式调用 `NotifyCanExecuteChanged()` 才会刷新按钮禁用态。

## 7. 验收标准

1. `dotnet build` 零错误；应用可从 Shell 启动并显示四个导航页。
2. 默认采集停止；点击开始后曲线持续推进，越限产生告警，值回落告警自动从活动列表消失。
3. 告警需先确认才能清除；历史告警可按级别/状态/时间查询并分页。
4. 工单可创建、指派、开始、完成；开始时按规则判定配方下发。
5. 配方列表来自配置，刷新可重载；修改阈值后刷新生效。
6. UI 布局、色彩、字体、文案与第 3 节描述及原文截图一致。
7. 停止采集/关闭窗口无定时器泄漏或异常。

## 8. 原文踩坑记录（实现时需规避）

- NModbus 的 Async 方法没有 `CancellationToken`。
- 艾尔赛继电器非标 Modbus 固定返回 8 路，请求 1 路会超时。
- S7.NetPlus 读 DB 区返回 `UInt32`，需按点位类型转换。
- SQLite 的 `busy_timeout` 是连接级 PRAGMA。
- Guid 插值格式 `:N0` 非法，会导致「假失败」。
- Prism `PubSubEvent` 无订阅者时事件直接丢弃。
- 计算属性做 `CanExecute` 必须显式 `NotifyCanExecuteChanged()`。
